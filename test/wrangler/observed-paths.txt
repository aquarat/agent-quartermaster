# Cloudflare API calls wrangler 4.165.0 makes through `aqmas cf env` (test/wrangler, 2026-11-20).
# Paths are below /client/v4, normalised: {acct} account id, {zone} zone id, {db} D1 uuid,
# {db-name} D1 database NAME (wrangler looks a name-only binding up by name in the path),
# {script} Worker name, {project} Pages project, {id} uuid/version/deployment id, {hash} asset hash.
# "(fake answered 404)": wrangler probes for objects that do not exist yet; the proxy must allow the call.
# [upload JWT] = the call carried the upload JWT as its credential (JWT passthrough);
# [synthetic] = answered by aqmasd itself (CLOUDFLARE.md 3.2), never reaches Cloudflare.
# Outside the shim: only wrangler's npm update check (CONNECT registry.npmjs.org:443), refused by
# the test's HTTPS_PROXY guard; no Cloudflare host was contacted except through the shim.
# Status per command:
#   wrangler whoami                 ok
#   wrangler deploy                 ok
#   wrangler versions upload        ok
#   wrangler secret put             ok
#   wrangler d1 execute             ok
#   wrangler d1 migrations apply    ok
#   wrangler pages deploy           ok
#   wrangler d1 execute (binding by name only) ok
#   wrangler deploy (single-asset uploads) ok
